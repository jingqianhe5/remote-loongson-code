# 3.3 矩阵乘法原理与设计

矩阵乘法是全连接层、卷积展开计算和轻量化语言模型推理中的主要计算形式。对于输入矩阵 $A\in\mathbb{R}^{M\times K}$ 和权重矩阵 $B\in\mathbb{R}^{K\times N}$，输出矩阵 $C\in\mathbb{R}^{M\times N}$ 的元素为

$$
C_{i,j}=\sum_{k=0}^{K-1}A_{i,k}B_{k,j}.
$$

直接由CPU执行该式，需要反复读取输入与权重，并在三层循环中完成乘法和累加。TPU将循环中的乘累加映射到规则的处理单元阵列，使输入、权重和部分和在相邻单元之间按拍流动。一个数据被送入阵列后可参与多个乘累加操作，权重也可在本地寄存器中复用，从而减少共享存储器访问次数。本设计参考TinyTPU中统一缓冲区、脉动阵列和向量处理单元分层组织的思路，并结合农芯种科SoC的8×8计算规模、Q8.8定点格式、AXI取数接口和LACC控制通路形成推理专用实现。当前版本只执行前向矩阵计算，不包含梯度求解、反向传播和片上参数更新。

## 3.3.1 基本结构

矩阵计算核心由AXI取指与DMA控制器、TPU指令译码器、统一缓冲区（Unified Buffer，UB）、8×8脉动阵列和向量处理单元（Vector Processing Unit，VPU）组成。CPU给出TPU程序首地址和数据描述符后，`tpu_axi_fetch_top`通过只读AXI主接口取得32位微指令与矩阵数据。微指令经`decode`模块转换为UB读写、权重切换和计算等待等控制信号，DMA数据则直接写入UB。UB按照指令指定的起始地址、行数、列数和转置标志产生错位数据流，将输入从阵列左侧送入，将权重从阵列顶部送入。阵列输出经过定点缩放与饱和后进入一级VPU寄存器，再由结果通路返回CPU。

```text
共享SRAM
   │  TPU程序、描述符、输入和权重
   ▼
AXI取指/DMA控制器 ──► 指令译码器
   │                       │ UB读写、切换、等待控制
   ▼                       ▼
统一缓冲区（2048×16位，8个银行）
   │ 输入流                         │ 权重流
   │ 从左向右                       │ 从上向下
   ▼                                ▼
             8×8 PE脉动阵列
   输入横向传播 ── 乘法 ── 部分和纵向传播
                         │
                         ▼
               Q16.16累加结果
                         │ 舍入、右移8位、饱和
                         ▼
                 Q8.8结果与有效位
                         │
                         ▼
                  VPU一级直通寄存器
                         │
                         ▼
                 TPU→CPU结果异步FIFO
```

图3-1 矩阵乘法核心数据通路

当前UB容量为2048个16位数据，并按阵列宽度划分为8个存储银行。连续地址的低3位选择银行，其余地址位选择银行内部行号。这种组织允许同一周期从不同银行为8条阵列通道供数，也便于AXI返回的32位数据以两个半字写入相邻地址。UB接收`ptr_select`区分输入矩阵、权重矩阵和偏置数据；当前推理通路实际使用输入与权重读口，训练所需的标签、激活导数和梯度读口被固定为零值兼容端口。矩阵维度和转置控制在发起一次UB读取时锁存，后续地址发生器根据脉动阵列的时空关系生成各通道有效信号。权重转置模式使软件可以按照自然矩阵布局存放权重，再由UB按列组织为阵列顶部需要的数据顺序。

脉动阵列包含64个相同的PE。每个PE接收一个16位有符号输入、一个16位有符号权重和来自上一行的32位部分和。输入及其有效信号向右传播，权重向下传播，部分和也沿列向下传递。PE内部计算关系为

$$
P_{r,c}^{(t)}=P_{r-1,c}^{(t-1)}+X_{r,c}^{(t)}W_{r,c}^{(t)},
$$

其中 $X$ 和 $W$ 均采用Q8.8格式，乘积保留完整32位Q16.16结果，部分和同样保持32位。早期实现若在每次乘法后立即缩窄到16位，小数乘积会被多次舍入，误差随$K$维累加而放大。当前设计把缩窄集中在阵列输出端：32位累加值先按照符号完成四舍五入，再算术右移8位恢复为Q8.8；超过`0x7FFF`或低于`0x8000`所表示范围的结果分别钳位到正、负饱和值，避免直接截断产生回绕。

每个PE设置有效权重寄存器和缓冲权重寄存器。新一组权重先写入缓冲寄存器，`SWITCH`控制到达相应PE后再提交为活动权重。该双缓冲方式使权重装载与当前计算在时序上解耦，也支持连续处理不同的$K$维分块。阵列依据矩阵列数关闭超出有效范围的PE列，并依据输入维度选择结果输出行，因此小于8列的尾块不必由软件填充成有效计算。大于8的$M$、$N$或$K$维矩阵仍需在软件侧分解为不超过8×8的微块，跨$K$块的最终累加由上层程序管理。

VPU在参考训练结构中可承担偏置、激活函数、损失和导数计算，但这些组合路径不属于当前推理核心。现有`vpu.v`仅将脉动阵列的8路结果及有效位寄存一拍后输出，归一化、复杂非线性层和跨块结果整理由软件完成。该取舍缩短了从阵列输出到写回端的组合路径，也使本节所述矩阵结果可以直接与软件定点参考模型比较。

## 3.3.2 TPU专用指令集

TPU内部使用独立于LoongArch指令的32位微指令。CPU只负责向TPU提供程序首地址，后续微指令由TPU通过AXI自主取回并顺序执行。指令最高4位为操作码，其余字段根据操作类型编码UB地址、矩阵尺寸、数据选择和等待条件。当前前向推理程序使用的指令见表3-1。

表3-1 TPU前向推理微指令

| 指令 | 操作码`[31:28]` | 主要字段 | 功能 |
|---|---:|---|---|
| `NOP` | `0x0` | 无 | 不改变计算状态，用于指令对齐或空操作 |
| `LOAD` | `0x1` | 地址`[27:16]`，16位数据`[15:0]` | 将一个Q8.8数据写入指定UB地址，主要用于小规模直接装载 |
| `SET_WR` | `0x2` | 写回地址`[27:16]`，累加位`[15]` | 设置后续阵列/VPU结果的UB写回位置；推理配置不启用UB内部累加 |
| `UB_READ` | `0x3` | 数据类型`[27:25]`，地址`[24:13]`，行数`[12:9]`，列数`[8:5]`，转置`[4]`，VPU模式`[3:0]` | 从UB读出一个矩阵块并送往输入、权重或偏置通路 |
| `SWITCH` | `0x4` | 无 | 将已装入缓冲寄存器的权重切换为活动权重 |
| `WAIT` | `0x5` | 等待类型`[27:24]`，上限`[23:0]` | 等待固定周期或等待权重、阵列、VPU有效数据完成，并提供超时保护 |
| `END` | `0xF` | 无 | 结束当前程序，待阵列结果排空后置完成状态 |

`UB_READ`是矩阵调度的核心指令。当`ptr_select=0`时，UB产生输入矩阵流；`ptr_select=1`时，UB产生权重流；`ptr_select=2`时选择偏置读口。行列字段各为4位，可描述单次微操作的局部矩阵尺寸，较大矩阵由多条指令分块处理。转置位主要服务于权重或转置乘法，VPU模式字段在当前推理版中保留编码但不改变结果，因为VPU已经固定为直通数据路径。

`WAIT`由AXI取指控制器直接识别，不送入普通译码器。等待类型0表示计数指定周期；类型1、2和3分别观察权重读口、VPU输出和脉动阵列输出的有效活动。对于事件型等待，控制器先检测有效信号出现，再等待其撤销，以此判断一段数据流已经结束；若在设定上限内没有完成，则置位执行错误。`END`同样由外层控制器处理，控制器在停止取指后继续保留结果排空窗口，防止末条计算指令产生的数据尚在阵列中传播就过早报告任务完成。

译码器中仍定义操作码`0x6`的`SET_GRAD_ADDR`，用于旧训练版本指定梯度地址。当前AXI集成顶层将学习率和`2/N`输入固定为零，UB也没有实现训练数据读出与参数更新路径，前向推理程序不发出该指令。因此`0x6`只属于源码兼容接口，不计入当前可用指令集。将这一边界写入指令定义，可以避免软件误用遗留编码后得到无效结果。

一组8×8矩阵微块的典型程序先用`UB_READ`装载权重，等待权重数据流结束后发出`SWITCH`；随后用`SET_WR`设置结果位置，再用另一条`UB_READ`送入输入矩阵，并等待阵列或VPU输出结束。多个$K$块重复这一过程，程序末尾通过`END`停止执行。微指令把数据布局、阵列控制和时序等待显式表达出来，CPU无需逐拍驱动PE，只需准备程序和矩阵数据。

## 3.3.3 与CPU的通信：基于龙芯的自定义指令集

TPU微指令解决加速器内部的数据调度，CPU与TPU之间则采用第1.3节所述LACC自定义指令。两级指令的作用范围不同：LACC属于LA500流水线可执行的控制指令，负责提交任务、查询状态和读取结果；TPU微指令存放在共享SRAM中，由加速器取指控制器解释，用于安排UB和脉动阵列的具体动作。CPU不需要理解每个PE的运行节拍，TPU也不直接进入LA500的通用指令流水线。

一轮矩阵任务由`TPU_CLEAR`清除上一轮状态开始。输入和权重较少时，CPU可用`UB_WRITE`逐个写入16位数据；常规矩阵采用`DMA_LOAD`提交描述符，描述符给出SRAM源字节地址、UB半字地址和传输长度，TPU随后以AXI突发方式自主读取数据。矩阵及权重就绪后，CPU执行`TPU_START`，将TPU程序首地址作为32位负载送入命令FIFO。加速器从该地址取回表3-1所示微指令，执行矩阵分块、权重切换和结果排空。CPU可在执行期间通过`TPU_STATUS`读取`busy`、`done`、`error`和结果数量，完成后用`TPU_READ`每次取得两个16位结果。

```text
LA500软件
  │ LACC: CLEAR / DMA_LOAD / START
  ▼
CPU→TPU命令异步FIFO
  │                         共享SRAM
  │                           │ TPU微指令、矩阵、权重
  ▼                           ▼
TPU命令控制 ──► AXI取指/DMA ──► UB ──► 8×8脉动阵列
                                              │
                                              ▼
LA500寄存器 ◄── LACC结果缓冲 ◄── TPU→CPU结果异步FIFO
  ▲
  └── LACC: STATUS / READ
```

图3-2 CPU与TPU的两级指令协同

CPU和TPU分别位于`cpu_clk`与`tpu_clk`时钟域，LACC命令及计算结果通过两条异步FIFO跨域，`busy`、`done`和`error`通过单比特同步器返回。命令FIFO保证`CLEAR—DMA_LOAD—START`按照软件提交顺序到达，结果FIFO以128位数据和8位有效掩码一次传递最多8个Q8.8结果。AXI只承担TPU程序、描述符和批量矩阵数据的传输，不承担LACC流水线握手；专用FIFO只传递控制和少量结果，也不替代AXI搬运大块矩阵。控制面与数据面分离后，CPU可以在TPU运行时继续执行其他代码，DMA取数还可与已启动的TPU程序重叠。

取指控制器内部设置两个64字的指令缓存槽。某一程序首地址第一次执行时，微指令由AXI逐字读取并填入缓存；同一首地址再次启动时可以直接回放缓存内容。缓存只保存到`END`为止的完整程序，`CLEAR`清除执行与DMA状态但保留指令缓存，因此重复矩阵微内核无需再次占用共享总线取指。当前TPU AXI端口只发起读事务，结果通过专用FIFO返回CPU，报告中不将其描述为可向共享SRAM直接写回的完整读写主设备。

## 3.3.4 梯度计算取舍与现存问题

TinyTPU参考源码曾包含损失函数、激活函数导数、梯度缓存和`gradient_descent`参数更新单元，可构成小型网络的片上训练闭环。农芯种科SoC当前目标是执行已经训练和量化的模型，矩阵乘法服务于前向推理。为此，综合路径中未实例化梯度下降模块，VPU删除损失和导数选择链，UB将标签、隐藏层导数和梯度读口作为固定零值的兼容端口，AXI集成顶层把学习率与`2/N`置零。该版本不能依据输出误差生成$\partial L/\partial W$，也不会执行$W\leftarrow W-\eta\partial L/\partial W$。模型训练、梯度计算和量化均在上位机完成，部署时只把定点权重和前向程序送入SoC。

不计算梯度减少了片上存储需求和后处理组合路径，但并不意味着矩阵乘法没有数值与调度问题。Q8.8只能表示约$[-128,127.996]$的数值，输入与权重乘积虽然以Q16.16保存在32位部分和中，较大的$K$维、异常权重或连续跨块累加仍可能使32位加法溢出。PE提供粘滞溢出标志，但当前阵列顶层没有把该标志汇总到CPU状态字。输出端饱和能避免16位回绕，却不能恢复已经在32位累加阶段溢出的真实数值。模型量化时应限制激活和权重范围，后续还应将阵列溢出汇总为可查询错误状态，或根据模型范围扩展累加位宽。

脉动阵列存在装填和排空延迟。输入、权重、有效信号及`SWITCH`需要穿过不同数量的PE，微指令不能只按理想乘法周期数连续发射。当前`WAIT`指令通过观察有效信号边沿或等待固定周期建立数据相关屏障，超时上限则防止错误尺寸或无数据输入使控制器永久停顿。这种显式等待易于验证，但固定等待值会增加空闲周期，事件型等待也依赖有效信号能够形成清晰的开始和结束。更高吞吐率的实现可在译码端加入记分牌，根据UB读事务和阵列流水级状态自动发射后继指令。

8×8固定阵列对非8倍数矩阵会产生尾块利用率下降。设计可根据有效列数关闭无效PE列，但尾块仍占用一次装填和排空过程；大于8的$K$维还需要多轮微块计算。当前推理配置关闭UB内部累加，跨$K$块的合并和部分结果整理主要由软件或LACC结果缓冲承担，增加了程序复杂度与结果传输量。若后续模型以长内积为主，可恢复经过验证的UB累加功能，或在阵列输出端增加更宽的分块累加缓存，但不能直接复用旧训练路径而不重新检查定点精度和存储冲突。

权重双缓冲能够隐藏部分装载时间，其正确性依赖`SWITCH`与权重数据在阵列中的传播关系。若切换过早，PE可能使用尚未完整装入的权重；若切换延迟，计算会落后一个权重块。当前验证通过连续使用不同对角缩放矩阵检查每个$K$块的切换结果，而不仅用相同单位矩阵重复测试。综合报告还显示PE乘法与加法路径尚未充分流水化，DSP乘法级寄存不足会限制最高时钟频率。增加乘法和累加寄存器可以改善时序，但会改变阵列延迟、`WAIT`参数和结果有效对齐关系，需要同步修改控制程序与验证模型。

阵列行选择逻辑也需覆盖边界尺寸。当前输出行由输入有效维度换算得到，并对0、超过8和单行情况分别处理。单行输入采用专门的物理行选择规则，表明该路径与UB错位送数存在实现耦合。现有矩阵测试以8元素微块和长$K$分块为主，后续应补充$1\times1$、$1\times8$、$7\times8$、转置尾块及正负极值组合，确认边界维度下的结果行和有效位不会错位。

## 3.3.5 仿真验证

矩阵乘法采用Verilator可执行测试平台进行模块级验证，测试顶层为`sim-verilator/tpu_dma_tb.sv`。测试平台构造可响应AXI读事务的片上存储器模型，在指定地址放置TPU微程序、DMA描述符、输入矩阵和权重，并直接例化`tpu_axi_fetch_top`。验证过程不读取RTL内部计算结果后自行修正，而是在`infer_result_data`和`infer_result_valid`接口捕获每一路Q8.8输出，再与测试平台预先计算的期望值逐项比较；任一数量、顺序或数值不匹配都会触发`$fatal`终止仿真。

表3-2 矩阵乘法仿真检查项目

| 检查项目 | 激励与判定方法 | 覆盖的设计要点 |
|---|---|---|
| DMA装载 | 通过描述符向UB的0和1024基地址各搬运576个半字，逐地址比较UB内容 | AXI突发、半字拆分、UB双区域寻址 |
| 计算与搬运重叠 | TPU执行等待程序期间提交另一笔DMA，统计两者同时忙的周期数必须大于0 | 取指控制与DMA并行、完成屏障 |
| 指令缓存 | 运行两个不同首地址的程序后再次启动首个程序，AXI取指次数不得增加 | 两槽程序缓存与`CLEAR`保留策略 |
| 基本矩阵乘法 | 8元素Q8.8输入乘8×8单位矩阵，共检查64个结果 | 数据顺序、权重转置、8路有效位和乘累加 |
| 重复执行 | 同一矩阵程序连续执行16次，每次结果数量均为64 | 清状态、缓存回放和阵列可重复性 |
| 权重切换 | 8个$K$微块分别使用1至8倍对角权重，并在UB两个基地址重复运行 | PE双缓冲、`SWITCH`传播、不同权重块对齐 |
| 小数精度 | 输入`0x0008`与正负`0x0010`权重完成8项累加，期望输出正负`0x0004` | Q16.16全精度部分和、仅在输出端舍入 |
| 输出饱和 | 构造超出Q8.8范围的正负结果，期望分别为`0x7FFF`和`0x8000` | 有符号缩放、上限与下限饱和 |

基本计算用例把每个输入微块设置为Q8.8编码的1至8，权重设置为单位矩阵，因而软件期望输出仍为1至8。该用例同时覆盖权重转置和8路结果顺序，但相同单位矩阵无法发现权重切换晚一个块的问题。测试平台随后把第$k$个微块的对角系数改为$k+1$，期望结果也按对应倍数变化，并分别在UB低地址区和1024起始的高地址区执行，以检查银行寻址与切换时序。

小数用例针对定点乘累加精度设置。Q8.8编码`0x0008`表示$8/256$，`0x0010`与`0xFFF0`分别表示$\pm16/256$。8个乘积在Q16.16中完整累加后，输出应为`0x0004`或`0xFFFC`。若每个乘积先缩窄再累加，结果会错误地变为两倍，因此该用例能够直接区分两种实现。饱和用例进一步构造绝对值为512的结果，其数值超出Q8.8范围，正确行为是钳位而不是截断回绕。

本节验证覆盖了矩阵核心、UB装载、内部指令等待、权重双缓冲和CPU侧任务所依赖的AXI控制边界。当前测试尚未覆盖所有非8倍数矩阵、32位累加器溢出上报和增加DSP流水级后的时序重对齐，这些项目保留为后续验证内容。由于设计不包含梯度计算，旧训练测试中的损失下降或权重更新不能作为当前矩阵乘法模块的验收依据。
