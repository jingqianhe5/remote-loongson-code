# 1.1 SoC整体架构

农芯种科 SoC 面向图像处理与轻量级智能推理任务，在同一系统中集成 LA500 处理器、TPU 张量计算单元、DMA 数据搬运引擎、ISP 图像处理模块、DVI 视频输出模块以及 UART 和板级配置外设。系统以 LA500 作为控制核心，负责程序执行、外设配置和任务调度；TPU 执行矩阵运算与推理计算；DMA 在共享存储器与流式数据接口之间搬运连续数据；ISP 完成图像增强和参数化处理。各模块通过统一的32位地址空间协同工作，使软件能够以存储器映射方式访问存储器和外设，同时保留加速器自主发起批量访存的能力。

## 1.1.1 系统组成与任务分工

系统数据通路以 BaseRAM 和 ExtRAM 组成的共享 SRAM 空间为中心。CPU 可从该空间取指和读写数据，DMA 可独立发起读写事务，TPU 则通过只读 AXI 主接口获取加速器程序、DMA 描述符和计算数据。UART、DVI、通用配置寄存器、DMA 配置接口和 ISP 配置接口作为目标设备接入统一互连。该结构没有要求 CPU 逐字搬运图像或矩阵数据，软件只需准备内存内容和任务参数，实际的数据读取可由 DMA 或 TPU 自主完成。

当前 AXI Crossbar 具有三个主设备侧输入，三者的职责见表1-1。CPU 接口从 `cpu_clk` 域跨入 `sys_clk` 域后，以系统侧 AXI 接口接入 Crossbar；DMA 原生工作在系统时钟域；TPU 的 AXI 接口从 `tpu_clk` 域跨入系统时钟域后接入 Crossbar。三个主设备均采用32位地址和32位数据接口，输入事务 ID 宽度为4位。

表1-1 AXI主设备及访问职责

| 主设备 | 所在时钟域 | AXI访问类型 | 主要职责 |
|---|---|---|---|
| LA500 CPU | `cpu_clk` | 读写，经AXI CDC接入 | 程序取指、数据访问、外设配置和任务调度 |
| DMA | `sys_clk` | 读写 | 在共享SRAM与流式接口之间搬运连续数据 |
| TPU | `tpu_clk` | 当前实现为只读，经AXI CDC接入 | 读取TPU程序、DMA描述符及批量计算数据 |

系统主要连接关系如图1-1所示。图中的实线表示 AXI 数据和存储器映射控制路径，虚线表示 CPU 与 TPU 之间的 LACC 专用命令、状态和结果路径。

图1-1 SoC整体架构与主要通信路径

图1-1将 CPU、DMA 和 TPU 置于同一级主设备侧，反映三者均可自主发起 AXI 事务。共享 SRAM 既保存 CPU 程序和通用数据，也可存放 TPU 程序、描述符、输入矩阵和权重。CPU 在完成数据与描述符准备后下发任务，TPU随后从共享 SRAM 取回相应内容并执行计算。DMA可在CPU只负责给出源地址、目的地址和长度的情况下完成批量搬运，从而使处理器流水线不必承担重复的数据复制工作。

ISP 在当前顶层中已经具有算法模块和独立配置接口，CPU可通过地址空间设置图像尺寸、亮度、对比度和白平衡等参数。当前 RTL 将直接视频输入保留为后续顶层集成点，尚未把外部视频源接入 ISP 像素通路，因此本节只描述已经实现的算法与配置结构，不将其表述为已经闭合的实时视频链路。DVI则保留新版与旧版两个地址窗口，顶层根据新版DVI的使能状态选择最终视频输出信号，便于兼容现有显示路径。

## 1.1.2 控制面与数据面分离

CPU 与 TPU 之间采用控制面和数据面分离的协同方式。批量数据属于数据面，包括 TPU 程序、DMA 描述符、输入张量和权重，这些内容存放在共享 SRAM 中，并由 TPU 的 AXI 只读主接口按需获取。CPU 不需要通过自定义指令逐项传输大块数据，也不需要占用自身数据总线代替 TPU 完成取数。

任务命令、少量直接写入数据、运行状态和推理结果属于控制与结果通路。LA500 内部的 LACC 单元将自定义指令转换为有序命令，经 CPU→TPU 异步 FIFO 送入 TPU 时钟域；TPU产生的结果经反向异步 FIFO返回 CPU时钟域；`busy`、`done` 和 `error` 等单比特状态通过两级同步寄存器返回。命令 FIFO 保持 `CLEAR`、数据准备和 `START` 等操作的先后关系，结果 FIFO 承担批量结果跨域，状态同步器则提供低开销的运行状态观察。

两类通路承担不同粒度的通信任务。AXI Crossbar 解决多个主设备访问共享存储器和存储器映射外设的问题，适合程序、描述符和连续数据传输；LACC与双异步FIFO建立CPU和TPU之间的紧耦合控制路径，适合命令下发、状态查询和结果读取。控制面不替代AXI数据面，数据面也不承担处理器自定义指令的流水线握手，二者在任务执行过程中相互配合。

## 1.1.3 时钟与复位域

系统由板载50 MHz时钟输入，经时钟生成模块得到 `cpu_clk`、`sys_clk` 和 `tpu_clk`。当前工程配置中，CPU时钟实际输出约为32.98 MHz，系统时钟和TPU时钟均为50 MHz。虽然 `sys_clk` 与 `tpu_clk` 的配置频率相同，但顶层仍为二者设置独立时钟、复位信号和跨域接口，不能仅依据频率相同将其视为同一同步时钟域。三个时钟域的职责见表1-2。

表1-2 系统时钟域及跨域关系

| 时钟域 | 当前频率 | 主要模块 | 跨域方式 |
|---|---:|---|---|
| `cpu_clk` | 约32.98 MHz | LA500流水线、LACC控制核心 | CPU AXI CDC；命令/结果异步FIFO；状态两级同步 |
| `sys_clk` | 50 MHz | AXI Crossbar、共享SRAM接口、DMA、UART、DVI、confreg、ISP | 与CPU和TPU分别通过AXI CDC连接 |
| `tpu_clk` | 50 MHz | TPU取指、数据加载和计算核心 | TPU AXI CDC；命令/结果异步FIFO |

时钟生成模块锁定后，系统复位先在 `sys_clk` 域同步释放，再分别同步到 CPU 和 TPU 时钟域。CPU 发出的完整 AXI 五通道信号通过 `Axi_CDC` 进入系统域，TPU AXI 接口也通过另一实例进入系统域，Crossbar本身只在 `sys_clk` 域内完成地址译码和仲裁。与任务顺序相关的LACC命令和多路计算结果不经过AXI CDC，而是使用专用异步FIFO跨越CPU与TPU时钟域。这样的边界划分使总线互连、处理器流水线和加速器能够使用各自适合的工作频率，同时把跨域处理集中在明确的接口位置。

# 1.2 AXI互连与地址空间

## 1.2.1 三主八目标端口互连

系统互连采用参数化 AXI Crossbar，当前顶层配置为 `S_COUNT=3`、`M_COUNT=8`，地址宽度和数据宽度均为32位。这里的三个输入端连接发起事务的 CPU 系统侧接口、DMA 和 TPU，八个输出端根据地址窗口连接共享 SRAM 与各类外设。Crossbar保留AXI独立读写通道、突发传输和多未完成事务能力，使DMA和TPU能够在CPU执行控制程序的同时发起存储访问。

CPU、DMA和TPU访问不同目标设备时，对应事务可在不同输出端口并行推进。例如，CPU配置ISP寄存器时，DMA仍可访问共享SRAM；当多个主设备同时请求共享SRAM时，对应输出端口的仲裁器采用轮询方式选择当前事务。读地址、读响应、写地址、写数据和写响应通道分别遵循AXI握手规则，写通道还保持地址与数据事务之间的对应关系，避免来自不同主设备的写数据发生混合。

每个主设备输入携带4位事务ID。由于Crossbar需要在返回响应时识别请求来源，目标设备侧ID宽度扩展为6位，即在原始事务ID之外编码三个输入端口的来源信息。读数据或写响应返回后，Crossbar依据扩展ID将响应送回原主设备，并向CPU、DMA或TPU恢复其4位ID。当前参数允许每个输入端接受最多16个并发操作，每个目标端最多发出4个未完成操作；实际并发程度仍受主设备行为、目标设备响应能力和访问冲突影响，不能仅由参数上限推导系统吞吐率。

## 1.2.2 地址译码与接口适配

Crossbar依据读地址或写地址的高位对事务进行译码。共享SRAM占用8 MB连续空间，其余外设窗口均按1 MB划分，当前地址映射见表1-3。M6窗口在顶层保留，当前未连接实际FFT或其他加速器功能；访问该窗口不能视为已有可用设备。未命中有效地址窗口的事务由互连返回译码错误响应，防止请求在总线上无目标地等待。

表1-3 AXI目标端口与地址空间

| Crossbar端口 | 地址范围 | 目标设备 | 当前功能 |
|---|---|---|---|
| M0 | `0x1C00_0000`～`0x1C7F_FFFF` | BaseRAM与ExtRAM | CPU程序、通用数据、TPU程序、描述符和计算数据 |
| M1 | `0x1100_0000`～`0x110F_FFFF` | 新版DVI | 新版视频帧缓冲访问与输出控制 |
| M2 | `0x1F00_0000`～`0x1F0F_FFFF` | UART | 串口收发和中断控制 |
| M3 | `0x1F10_0000`～`0x1F1F_FFFF` | 旧版DVI | 兼容原有视频输出路径 |
| M4 | `0x1F20_0000`～`0x1F2F_FFFF` | confreg | LED、数码管、拨码开关、按键和中断控制 |
| M5 | `0x1F30_0000`～`0x1F3F_FFFF` | DMA配置 | DMA源地址、目的地址、长度、启动和状态寄存器 |
| M6 | `0x1F40_0000`～`0x1F4F_FFFF` | 预留 | 为后续加速器或外设扩展保留 |
| M7 | `0x1F50_0000`～`0x1F5F_FFFF` | ISP配置 | ISP算法选择、图像尺寸及算法参数配置 |

共享 SRAM、UART、DVI 和 confreg 直接使用完整 AXI 接口。DMA 与 ISP 的配置寄存器采用 AXI-Lite 接口，系统在 M5 和 M7 端口分别插入 AXI-to-AXI-Lite 适配器，将 Crossbar 输出的突发与ID相关信号转换为单次寄存器访问。数据搬运本身并不经过 DMA 的配置端口：CPU通过M5写入任务参数，DMA随后以独立AXI主设备身份重新访问Crossbar。ISP同样通过M7接收控制参数，而像素数据使用独立流式接口处理，从而避免把寄存器配置流量与连续像素流混为一条数据路径。

## 1.2.3 互连在异构任务中的作用

一轮异构任务通常由CPU在共享SRAM中准备程序、描述符和输入数据开始。CPU随后通过存储器映射寄存器配置DMA或ISP，并通过LACC指令向TPU下发数据加载与启动命令。DMA和TPU取得总线控制权后，可分别发起突发传输或只读访问；Crossbar根据地址将请求送往共享SRAM，并在发生端口竞争时完成轮询仲裁。TPU执行结束后，少量状态和计算结果通过专用FIFO返回CPU，大块数据仍留在共享存储空间供后续模块访问。

这种组织方式把通用共享访问与紧耦合控制放在不同层次：AXI Crossbar提供统一地址空间、并发访问和响应路由，LACC通路提供CPU—TPU之间的低开销命令与结果交互。后续1.3节将在这一系统结构基础上，进一步说明LA500内部的自定义指令译码、流水线阻塞、命令握手和结果写回机制。
