# 1.3 CPU内部基于龙芯的自定义指令集修改

## 1.3.1 指令扩展目的

农芯种科 SoC 采用 LA500 作为系统控制核心，TPU 负责矩阵计算和推理加速。若完全使用存储器映射寄存器控制 TPU，CPU 每次启动任务都需要通过 AXI 总线完成地址计算、寄存器写入和状态轮询，少量参数传递也会被拆分为多条普通指令及总线事务。这种方式适合通用外设，但在 CPU 频繁调度 TPU、分块加载输入并读取多组结果的场景下，控制开销会随任务次数累积。

为建立低开销的 CPU—TPU 控制通路，本设计在 LA500 内部增加 LACC（LoongArch Accelerator）自定义指令支持。LACC 指令沿用处理器原有寄存器读写和流水线写回机制，以通用寄存器 `rj`、`rk` 传入 TPU 程序地址、UB 地址、数据或描述符地址，并通过目的寄存器 `rd` 返回状态字或计算结果。批量指令和数据仍由 TPU 的 AXI 主接口从 SRAM 读取，自定义指令只承担任务控制、少量数据写入和结果读取，因而没有用专用控制通路替代系统总线的数据搬运功能。

这一修改在 CPU 内部形成了“指令译码—LACC 执行—命令下发—状态或结果写回”的完整路径。软件不再直接操作一组 TPU 控制寄存器，而是将 TPU 控制表达为处理器指令，使加速器调用能够参与正常的寄存器相关性检查、流水线暂停和异常冲刷。

## 1.3.2 自定义指令编码

LACC 指令采用 32 位定长编码。当前软件以 `0xC0` 作为高 8 位主操作码，`command` 字段位于 `[23:22]`，立即数字段 `imm` 位于 `[21:15]`，`rk`、`rj` 和 `rd` 沿用通用寄存器编号。其格式如下：

```text
31             24 23       22 21             15 14       10 9         5 4         0
+----------------+-----------+-----------------+-----------+-----------+-----------+
| 主操作码 0xC0 | command   |      imm        |    rk     |    rj     |    rd     |
+----------------+-----------+-----------------+-----------+-----------+-----------+
       8位            2位           7位             5位         5位         5位
```

CPU 可见的主命令共有四类。`START`、`STATUS` 和 `CLEAR` 由 `command` 直接确定；`command=2'b10` 时，再由 `imm` 区分结果读取、UB 单点写入、结果模式设置和批量数据加载。当前指令定义见表 1-1。

表 1-1 LACC 自定义指令定义

| CPU主命令 | `command` | `imm` | 输入操作数 | 返回值 | 功能 |
|---|---:|---:|---|---|---|
| `TPU_START` | `2'b00` | — | `rj`：TPU程序首地址 | 当前状态字 | 将程序地址作为有序命令送入 TPU，并启动取指执行 |
| `TPU_STATUS` | `2'b01` | — | 无 | TPU状态字 | 读取 busy、done、error、结果数量和错误码 |
| `TPU_READ` | `2'b10` | `7'd0` | `rj[5:0]`：结果对索引 | 两个16位结果 | 从 LACC 结果缓冲区读取一对结果 |
| `UB_WRITE` | `2'b10` | `7'd1` | `rj[15:0]`：UB半字地址；`rk[15:0]`：数据 | 当前状态字 | 向 TPU Unified Buffer 写入一个16位数据 |
| `SET_MODE` | `2'b10` | `7'd2` | `rj[0]`：结果模式 | 当前状态字 | 选择分类折叠累加或原始顺序存储模式 |
| `DMA_LOAD` | `2'b10` | `7'd3` | `rj`：DMA描述符地址 | 当前状态字 | 命令 TPU 从 SRAM 批量加载数据到 UB |
| `TPU_CLEAR` | `2'b11` | — | 无 | 清除前的状态字 | 清除 LACC 结果、错误状态及 TPU 执行/DMA完成状态 |

CPU 指令中的 `command` 与异步命令 FIFO 中的 `op` 属于两套不同编码。`TPU_STATUS`、`TPU_READ` 和 `SET_MODE` 只访问 CPU 时钟域内的 LACC 状态或结果缓冲区，不需要发送到 TPU。会改变 TPU 状态的四种操作被转换成 FIFO 命令，映射关系见表 1-2。

表 1-2 LACC 指令与 TPU FIFO 命令的映射

| LACC操作 | FIFO `op` | FIFO `payload` | 是否跨入 `tpu_clk` 域 |
|---|---:|---|---|
| `TPU_CLEAR` | `2'b00` | 无有效参数 | 是 |
| `TPU_START` | `2'b01` | `rj[31:0]`，TPU程序首地址 | 是 |
| `UB_WRITE` | `2'b10` | `{rj[15:0], rk[15:0]}` | 是 |
| `DMA_LOAD` | `2'b11` | `rj[31:0]`，描述符地址 | 是 |
| `TPU_STATUS` | — | — | 否，LACC本地读取 |
| `TPU_READ` | — | — | 否，LACC本地读取 |
| `SET_MODE` | — | — | 否，LACC本地修改 |

这种分层编码保留了四种 CPU 主命令的紧凑格式，同时利用立即数字段扩展数据准备和结果管理功能。跨时钟 FIFO 只传递会影响 TPU 执行顺序的命令，从而保证 `CLEAR—DMA_LOAD—START` 等操作按照 CPU 发出的先后次序到达 TPU。

## 1.3.3 CPU流水线修改

LACC 指令进入 LA500 后，译码级根据指令高位识别自定义操作，并从 `[23:22]` 提取 `command`。译码逻辑将 LACC 纳入合法指令集合，同时把它加入 `rj`、`rk` 源寄存器需求判断，使现有的数据相关检测和前递逻辑能够覆盖自定义指令。`command` 和请求有效位随 `ds_to_es_bus` 进入执行级，原流水级间总线宽度也相应增加。

执行级从译码结果中取得 `rj`、`rk` 的32位操作数，并从立即数通路提取 `imm[6:0]`，随后向 `lacc_core` 发出请求。对于 `STATUS`、`READ` 和 `SET_MODE` 等本地操作，LACC 可在当前请求周期给出响应；对于需要写入异步命令 FIFO 的 `START`、`UB_WRITE`、`DMA_LOAD` 和 `CLEAR`，只有 `lacc_tpu_cmd_ready` 有效时，请求才被接受。

当命令 FIFO 暂时无法接收数据时，`lacc_rsp_valid` 保持无效，执行级由下式产生阻塞：

```text
lacc_stall = es_lacc_req && !lacc_rsp_valid
```

阻塞期间，执行级保留当前 LACC 指令，不允许其进入后续流水级，也不会重复提交命令。FIFO 恢复可写后，`valid/ready` 握手完成，执行级解除暂停。这种反压机制把跨时钟 FIFO 的容量状态纳入处理器流水线控制，避免命令丢失或同一指令被多次执行。

LACC 的32位响应通过执行结果选择器接入原有数据通路。当当前指令为 LACC 请求时，`lacc_rsp_rdat` 取代普通 ALU 结果，随后沿执行、访存和写回流水级写入 `rd`。该结果同时接入执行级前递网络，因此紧随其后的指令能够按照原有处理器规则处理数据相关。接口中预留了 `lacc_flush`，设计意图是在异常、返回或其他流水线冲刷时清理 LACC 本地状态，防止已取消指令继续产生控制作用。当前 `exe_stage.v` 只声明并向外连接了该信号，尚未给出明确驱动，因此这一冲刷保护仍需补充赋值并通过仿真验证，不能作为已经生效的功能。

## 1.3.4 LACC控制核心

`lacc_core` 位于 CPU 时钟域，是流水线与 TPU 控制通路之间的接口。该模块接收执行级给出的 `command`、`imm`、`rj` 和 `rk`，完成子操作判定、FIFO 命令生成、状态字拼接以及结果缓存。命令下发接口采用 `valid/ready` 握手，输出包括2位命令类型和32位负载；状态反馈接口接收同步后的 `tpu_busy`、`tpu_done` 和 `tpu_error`。

LACC 返回的状态字格式见表 1-3。软件可通过一条 `TPU_STATUS` 指令获得运行状态、结果数量和错误信息，不需要对多个寄存器分别发起总线读取。

表 1-3 LACC状态字定义

| 位域 | 名称 | 含义 |
|---|---|---|
| `[31:24]` | Reserved | 保留，当前为0 |
| `[23:16]` | `error_code` | 最近一次错误码 |
| `[15:8]` | `result_count` | 已接收的16位结果数量 |
| `[7:6]` | Reserved | 保留，当前为0 |
| `[5]` | `raw_mode` | 1表示原始结果顺序存储，0表示分类折叠累加 |
| `[4]` | `result_overflow` | 结果超出缓冲容量 |
| `[3]` | `result_full` | 结果缓冲达到当前模式的完成条件 |
| `[2]` | `error` | LACC或TPU错误 |
| `[1]` | `done` | TPU任务完成 |
| `[0]` | `busy` | TPU正在执行 |

结果返回侧设置了64个16位槽位及64位有效标志。TPU每次最多返回8路16位结果，LACC根据有效掩码写入缓冲区。原始模式按照到达顺序保存结果，适合通用矩阵乘法；分类模式按照结果位置完成折叠累加，用于数字识别等分类任务。`TPU_READ` 以 `rj[5:0]` 为结果对索引，一次将相邻两个16位结果拼接为32位数据写回 `rd`。索引越界、读取无效位置、TPU硬件错误和非法命令分别记录错误状态及错误码，软件可以通过状态字统一判断。

## 1.3.5 CPU—TPU协同流程

CPU 与 TPU 分别工作在 `cpu_clk` 和 `tpu_clk` 时钟域。LACC 产生的有序命令先写入 CPU→TPU 异步 FIFO，TPU侧按顺序取出 `CLEAR`、`START`、`UB_WRITE` 或 `DMA_LOAD`。TPU产生的128位结果及8位有效掩码通过反向异步 FIFO返回 CPU，LACC再将其整理到本地结果缓冲区。`busy`、`done` 和 `error` 属于单比特状态，采用两级同步寄存器返回 CPU，不占用结果 FIFO。

一轮典型任务从 `TPU_CLEAR` 开始，用于清除上一轮执行状态和本地结果有效位。输入规模较小时，CPU可使用 `UB_WRITE` 将单个16位数据直接送入 UB；输入、权重或矩阵规模较大时，CPU通过 `DMA_LOAD` 给出 SRAM 中的描述符地址，由 TPU 的 AXI 只读主接口批量装载数据。数据准备完成后，`TPU_START` 将 SRAM 中的 TPU 程序首地址送入命令 FIFO，TPU取指并执行。CPU在此期间使用 `TPU_STATUS`查询运行状态，在 `done` 置位且结果数量满足要求后，通过 `TPU_READ`读取结果。

```text
CPU执行LACC指令
       │
       ├── CLEAR / UB_WRITE / DMA_LOAD / START
       │                 │
       │                 ▼
       │        CPU→TPU命令异步FIFO
       │                 │
       │                 ▼
       │          TPU取指、加载和计算
       │                 │
       │                 ▼
       │        TPU→CPU结果异步FIFO
       │                 │
       └── STATUS / READ ◄┴── LACC状态与结果缓冲
```

该协同方式把控制面和数据面分开：LACC与双 FIFO负责低延迟控制、状态和结果交互，AXI Crossbar负责 TPU 程序、描述符及批量计算数据的传输。两条通路相互配合，使自定义指令不会占用 CPU 数据总线搬运大块数据，同时保留 TPU 独立访问共享 SRAM 的能力。

## 1.3.6 软件调用与验证

当前 LoongArch 裸机工具链尚未定义这些 LACC 助记符，软件采用内联汇编 `.word` 直接嵌入32位机器码。调用函数先把输入参数移动到指令指定的 `rj`、`rk` 寄存器，执行机器码后再从 `rd` 取回状态或结果。表 1-4列出了当前软件使用的编码实例，其中 `$r5`、`$r6` 分别作为 `rj`、`rk`，`$r4` 作为返回寄存器 `rd`。

表 1-4 软件使用的LACC机器码

| 操作 | 机器码 | 主要寄存器约定 |
|---|---:|---|
| `TPU_START` | `0xC00000A4` | `$r5`传入程序首地址，结果写入`$r4` |
| `TPU_STATUS` | `0xC0400004` | 状态字写入`$r4` |
| `TPU_READ` | `0xC08000A4` | `$r5`传入结果对索引，结果写入`$r4` |
| `UB_WRITE` | `0xC08098A4` | `$r5`传入UB地址，`$r6`传入16位数据 |
| `SET_MODE` | `0xC08100A4` | `$r5[0]`选择结果模式 |
| `DMA_LOAD` | `0xC08198A4` | `$r5`传入DMA描述符地址 |
| `TPU_CLEAR` | `0xC0C00004` | 无输入，状态字写入`$r4` |

RTL仿真应检查译码级 `lacc_req` 与 `command` 是否匹配机器码，执行级在 FIFO `ready` 拉低时是否保持当前指令，以及握手恢复后命令是否只写入一次。CPU—TPU 联合仿真还需观察两个异步 FIFO的写入与读出顺序、TPU状态同步、结果有效掩码和 LACC 结果缓冲内容。上板测试可由软件依次执行 `CLEAR、DMA_LOAD或UB_WRITE、START、STATUS、READ`，记录状态字、结果数据和处理器周期计数，并与软件参考结果比较。测试数据和波形完成后，可据此补充指令延迟、任务执行周期及结果正确性等量化指标。
