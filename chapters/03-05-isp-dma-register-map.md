# ISP与DMA总线寄存器说明

本SoC将DMA和ISP的配置接口作为AXI目标设备挂接到系统Crossbar。CPU通过存储器映射寄存器设置参数，DMA随后以独立AXI主设备身份访问共享SRAM；ISP寄存器只承担算法选择和参数配置，像素数据使用独立视频流接口。两者的配置通路均经过AXI-to-AXI-Lite适配器，寄存器数据宽度为32位。

## 1. 总线地址映射

Crossbar为DMA和ISP各分配1 MB地址窗口。裸机程序使用`0xB...`非缓存地址访问外设，进入系统总线后对应`0x1...`物理窗口。寄存器绝对地址等于基地址与寄存器偏移之和。

| 设备 | Crossbar端口 | AXI物理地址窗口 | CPU非缓存基地址 | 配置接口 | 数据接口 |
|---|---:|---|---|---|---|
| DMA | M5 | `0x1F30_0000`～`0x1F3F_FFFF` | `0xBF30_0000` | AXI-Lite从接口 | 32位AXI主接口与AXI-Stream |
| ISP | M7 | `0x1F50_0000`～`0x1F5F_FFFF` | `0xBF50_0000` | AXI-Lite从接口 | 24位RGB视频流接口 |

DMA配置端口和DMA数据通路承担不同职责。CPU对M5窗口的访问只修改地址、长度、命令和状态寄存器；真正的数据搬运由DMA主接口重新进入Crossbar完成。ISP配置端口同样不传输图像内容，图像使用`video_in_*`和`video_out_*`流信号进入、离开`isp_core`。

## 2. DMA寄存器

DMA寄存器以`0x1F30_0000`为AXI物理基地址，以`0xBF30_0000`为CPU非缓存基地址。地址和长度寄存器在启动前由CPU写入，命令寄存器把配置转换成读写描述符，状态寄存器用于判断描述符通道是否可接收任务以及任务是否完成。

| 偏移 | AXI物理地址 | CPU访问地址 | 访问属性 | 复位值 | 功能 |
|---:|---|---|---|---:|---|
| `0x00` | `0x1F30_0000` | `0xBF30_0000` | R/W | `0x0000_0000` | DMA读源地址，保存完整32位AXI地址 |
| `0x04` | `0x1F30_0004` | `0xBF30_0004` | R/W | `0x0000_0000` | DMA读长度，只有`[19:0]`有效，单位为字节 |
| `0x08` | `0x1F30_0008` | `0xBF30_0008` | R/W | `0x0000_0000` | DMA写目的地址，保存完整32位AXI地址 |
| `0x0C` | `0x1F30_000C` | `0xBF30_000C` | R/W | `0x0000_0000` | DMA写长度，只有`[19:0]`有效，单位为字节 |
| `0x10` | `0x1F30_0010` | `0xBF30_0010` | W，读回0 | `0x0000_0000` | 命令寄存器：bit0启动读，bit1启动写 |
| `0x14` | `0x1F30_0014` | `0xBF30_0014` | R | `0x0000_0000` | DMA状态寄存器，位定义见表2-2 |

表2-2 DMA状态寄存器`DMA_STATUS`（偏移`0x14`）

| 位 | 名称 | 含义 |
|---:|---|---|
| `[0]` | `read_cmd_ready` | DMA读描述符接口可以接收命令 |
| `[1]` | `write_cmd_ready` | DMA写描述符接口可以接收命令 |
| `[2]` | `dma_busy` | 已提交的读或写任务尚未全部完成 |
| `[3]` | `dma_done` | 本轮任务完成；下一次有效启动时清零 |
| `[4]` | `read_cmd_valid` | 读命令正在等待与DMA握手 |
| `[5]` | `write_cmd_valid` | 写命令正在等待与DMA握手 |
| `[6]` | `read_pending` | 本轮读描述符已启动，尚未收到完成状态 |
| `[7]` | `write_pending` | 本轮写描述符已启动，尚未收到完成状态 |
| `[8]` | `read_desc_seen` | 本轮已经收到读描述符完成状态 |
| `[9]` | `write_desc_seen` | 本轮已经收到写描述符完成状态 |
| `[31:10]` | Reserved | 保留，读回0 |

写`DMA_CMD=0x1`只启动存储器读取并从AXI-Stream读数据口输出；写`DMA_CMD=0x2`只启动写通道，数据需要由AXI-Stream写数据口提供；写`DMA_CMD=0x3`同时启动读写，当前顶层把DMA读出的流直接回接写入流，因此可完成源地址到目的地址的数据复制。读写长度应保持一致，否则较短一侧结束后可能使另一侧等待数据或丢弃多余数据。

典型内存复制顺序如下：

```c
#define DMA_BASE       0xBF300000u
#define DMA_READ_ADDR  (*(volatile unsigned int *)(DMA_BASE + 0x00))
#define DMA_READ_LEN   (*(volatile unsigned int *)(DMA_BASE + 0x04))
#define DMA_WRITE_ADDR (*(volatile unsigned int *)(DMA_BASE + 0x08))
#define DMA_WRITE_LEN  (*(volatile unsigned int *)(DMA_BASE + 0x0C))
#define DMA_CMD        (*(volatile unsigned int *)(DMA_BASE + 0x10))
#define DMA_STATUS     (*(volatile unsigned int *)(DMA_BASE + 0x14))

while ((DMA_STATUS & 0x3u) != 0x3u) { }
DMA_READ_ADDR = src_axi_addr;
DMA_READ_LEN = byte_count;
DMA_WRITE_ADDR = dst_axi_addr;
DMA_WRITE_LEN = byte_count;
__asm__ __volatile__("dbar 0" : : : "memory");
DMA_CMD = 0x3u;
while (DMA_STATUS & (1u << 2)) { }
```

长度寄存器为20位，单条描述符可表示的最大长度为`0xF_FFFF`字节。源地址和目的地址必须是DMA主接口能够访问的AXI地址，不能直接写入CPU的`0xB...`非缓存别名。当前`axi_dma`数据宽度为32位，软件还应保证地址、长度和字节使能满足目标设备的数据对齐要求。

## 3. ISP寄存器

ISP寄存器以`0x1F50_0000`为AXI物理基地址，以`0xBF50_0000`为CPU非缓存基地址。除启动寄存器外，其余配置寄存器均支持读回；AXI写入使用`WSTRB`控制字节生效范围。

| 偏移 | AXI物理地址 | CPU访问地址 | 访问属性 | 复位值 | 功能 |
|---:|---|---|---|---:|---|
| `0x00` | `0x1F50_0000` | `0xBF50_0000` | W，读回0 | `0x0000_0000` | bit0写1产生一个周期的`frame_start_pulse` |
| `0x04` | `0x1F50_0004` | `0xBF50_0004` | R/W | `0x0000_0000` | ISP算法选择，`[8:0]`有效 |
| `0x08` | `0x1F50_0008` | `0xBF50_0008` | R/W | `0x0000_0080` | 亮度参数，128为不调整 |
| `0x0C` | `0x1F50_000C` | `0xBF50_000C` | R/W | `0x0000_0080` | 对比度Q1.7增益，128表示1.0倍 |
| `0x10` | `0x1F50_0010` | `0xBF50_0010` | R/W | `0x0000_0000` | AWB红通道参数；当前只保存和读回 |
| `0x14` | `0x1F50_0014` | `0xBF50_0014` | R/W | `0x0000_0000` | AWB绿通道参数；当前只保存和读回 |
| `0x18` | `0x1F50_0018` | `0xBF50_0018` | R/W | `0x0000_0000` | AWB蓝通道参数；当前只保存和读回 |
| `0x1C` | `0x1F50_001C` | `0xBF50_001C` | R/W | `0x0000_0000` | 图像宽度，`[15:0]`有效 |
| `0x20` | `0x1F50_0020` | `0xBF50_0020` | R/W | `0x0000_0000` | 图像高度，`[15:0]`有效 |

亮度模块把寄存器值解释为以128为中心的有符号调节量。数值大于128时，各RGB通道增加`value-128`并在255处饱和；数值小于128时，各通道减去`128-value`并在0处饱和。对比度模块使用Q1.7增益，计算关系可写为

```text
output = saturate((((input - 128) * contrast) >> 7) + 128)
```

ISP的数据处理顺序为灰度/Gamma、空间滤波、锐化、特殊处理、对比度和亮度。同一个`ISP_SELECTOR`可以同时开启多个阶段，各阶段按照该顺序串行作用于像素。

## 4. ISP_SELECTOR位域

`ISP_SELECTOR`使用9位控制四组算法，位域之间可以组合。未列出的编码均走旁路。

| 位域 | 编码 | 功能 | 使用条件或限制 |
|---|---:|---|---|
| `[8:7]` | `2'b00`、`2'b01` | RGB旁路 | 不进行灰度转换 |
| `[8:7]` | `2'b10` | RGB转灰度 | 产生三个通道相同的灰度数据 |
| `[8:7]` | `2'b11` | 灰度后进行Gamma变换 | Gamma查找表作用于灰度数据 |
| `[6:4]` | `3'b001` | 双边滤波选择码 | 当前实例被注释，不能作为可用功能 |
| `[6:4]` | `3'b010` | 均值滤波 | 对输入图像进行平滑 |
| `[6:4]` | `3'b011` | 中值滤波 | 对脉冲噪声进行抑制 |
| `[6:4]` | `3'b100` | 高斯滤波 | 只有`selector[8]=1`时执行，否则旁路 |
| `[3:2]` | `2'b01` | Sobel锐化 | 对RGB三个通道分别计算梯度并增强 |
| `[3:2]` | `2'b10` | Laplacian锐化 | 使用Laplacian算子增强高频分量 |
| `[3:2]` | `2'b11` | Robert锐化 | 使用Robert交叉梯度增强边缘 |
| `[1:0]` | `2'b01` | 二值化 | 只有`selector[8]=1`时执行 |
| `[1:0]` | `2'b10` | Sobel边缘检测 | 只有`selector[8]=1`时执行 |

常用选择值见表4-2。

| 处理模式 | `ISP_SELECTOR` | 说明 |
|---|---:|---|
| 全部旁路 | `0x000` | 保持RGB数据，仅应用后级亮度和对比度参数 |
| 灰度 | `0x100` | `[8:7]=2'b10` |
| 灰度+Gamma | `0x180` | `[8:7]=2'b11` |
| 灰度+高斯滤波 | `0x140` | 灰度`0x100`与高斯`0x040`组合 |
| 彩色Sobel锐化 | `0x004` | `[3:2]=2'b01` |
| 灰度+高斯+Sobel锐化 | `0x144` | 三个处理阶段串行执行 |
| 灰度+二值化 | `0x101` | `[1:0]=2'b01` |
| 灰度+Sobel边缘检测 | `0x102` | `[1:0]=2'b10`，不是Sobel锐化 |

`isp_test/main.c`当前写入的`0x102`表示灰度转换后进行Sobel边缘检测。若要得到前一节生成的高斯滤波效果，应写入`0x140`；若要进行彩色Sobel锐化，应写入`0x004`。配置完成后，软件执行内存屏障，再向偏移`0x00`写1产生帧启动脉冲。

## 5. 当前实现边界

DMA目录中存在两个同名`dma_config_axil`模块。`rtl/ip/verilog-axi-master/rtl/dma_config_axil.v`带有描述符完成状态输入，其寄存器`0x14`实现表2-2的bit0～bit9；`rtl/ip/dma_config_axil.v`是简化版，只在bit0和bit1返回读写ready。`soc_top.v`连接了`read_desc_status_valid`和`write_desc_status_valid`，其端口列表与增强版一致。工程文件列表应只编译与顶层端口匹配的版本，避免同名模块重复定义或状态位缺失。

ISP的AWB、宽度、高度和帧启动寄存器已经能够保存、读回或产生脉冲，但当前`isp_top.v`只把算法选择、亮度和对比度送入实际处理核心。AWB参数没有接入白平衡算法，宽高与启动脉冲被保留给后续帧源适配器。当前SoC顶层还把ISP视频输入固定为无效和零数据，因此寄存器访问可以通过AXI-Lite仿真验证，但在接通实际视频源之前，不能依据寄存器配置成功推断已经产生处理后的图像流。
